# Publishing rules

These keep the write-ups useful and safe to share.

1. **After the event only.** Do not publish solutions or flags while a contest is running, and follow any
   rule the organizers set about publishing.
2. **No live malware.** Describe samples by name and hash. Never commit a live sample, and never a working
   weaponized exploit for a real, unpatched product.
3. **No private data.** Remove credentials, tokens, internal addresses and anything that identifies a
   person who did not agree to it.
4. **Unreported vulnerabilities stay private.** If a challenge exposed a real flaw in a real product, report
   it to the vendor first and wait for the disclosure window.
5. **Credit the team.** Name teammates and any write-up or tool that helped.
6. **Respect licenses.** Challenge files belong to their authors. Link to them instead of copying them here
   unless the organizers allow redistribution.
7. **Say what you do not know.** If a step is a guess, mark it as one.
